# 2026-08-11 项目业务逻辑加固

本次更新集中修复认证、套餐限制、学员课程权限、学习进度、用户生命周期和域名绑定任务中的一致性与可靠性问题。

## 主要变更

- 公共注册只允许创建学员；超级管理员首次初始化必须使用独立的启动密钥，并由数据库保证只能创建一个全局超级管理员。
- 启动时校验数据库密码、JWT 密钥和可选的超级管理员启动密钥，阻止默认或过短密钥进入运行环境。
- 套餐员工数与课程数限制统一解析显式套餐或启用中的默认套餐；数值 `0` 仍表示不限制。
- 普通租户课程必须先分配给学员才能学习；启用的官方课程可在首次学习时自动建立报名记录。
- 必修/选修只以课程的 `course_type` 为准，历史报名字段不再覆盖课程分类。
- PC 和 H5 共用学习心跳控制器。心跳新增稳定的 `session_id`，后端按服务端观察到的会话时长校验累计学习时间，并保持进度单调不回退。
- 删除学员改为停用账号（`status = 0`），学习进度、报名和学习时长记录继续保留；停用账号不可登录。
- 域名绑定任务写入 `domain_bind_jobs`，验证、配置、失败和重试状态可在进程重启后恢复，并通过租户与域名唯一约束防止重复占用。

## 部署要求

部署前确认 `.env` 至少配置：

```env
DB_PASSWORD=<非空数据库密码>
JWT_SECRET=<至少 32 个字符的随机密钥>
SUPERADMIN_BOOTSTRAP_SECRET=<启用首次超级管理员初始化时，至少 32 个字符>
```

`docker-compose.yml` 不再为 `DB_PASSWORD` 和 `JWT_SECRET` 提供生产回退值。若系统已经完成超级管理员初始化，可以留空 `SUPERADMIN_BOOTSTRAP_SECRET` 以关闭初始化入口。

## 数据库迁移

- v22：增加全局超级管理员唯一约束。
- v23：学习心跳增加 `session_id` 及会话查询索引。
- v24：新增持久化域名绑定任务表及租户、域名唯一约束。

应用启动时会按版本自动迁移。部署顺序建议为：备份数据库 → 更新环境变量 → 发布后端并完成迁移 → 发布前端。

## 兼容与回滚

- 不带心跳字段的旧版“仅位置进度”请求仍可使用，但不会增加学习时长。
- `course_enrollments.assignment_type` 字段继续保留用于响应兼容，学员端分类改由课程本身决定。
- 用户删除接口的 HTTP 形态不变，语义改为停用。
- 回滚应用代码前不要删除 v22–v24 的表和索引；旧版本会忽略新增字段和表。若确需数据库回滚，应先备份并确认不会恢复公共特权注册或硬删除学员等旧行为。
