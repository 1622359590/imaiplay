# 用户可读错误与连续资源上传设计

## 目标

1. 管理后台、PC 学习端和 H5 学习端不再直接展示 Axios、HTTP 或内部英文错误，而是展示普通用户能理解的中文提示。
2. 管理后台资源列表上传成功后继续显示上传框，方便连续上传；其他需要单文件预览、替换和移除的上传场景保持不变。

## 用户可读错误

在 `web/shared` 增加统一的用户错误转换入口，各端只展示该入口返回的文案。

转换顺序：

1. 保留后端返回的明确中文业务提示。
2. 将已知英文业务错误映射为对应中文文案。
3. 根据网络异常、超时和 HTTP 状态码生成通用中文提示。
4. 对未知英文、Axios 默认文案和内部异常使用当前操作的中文兜底文案，绝不直接显示原始技术信息。

常见状态文案包括：登录凭证错误或失效、权限不足、内容不存在、数据冲突、文件过大、操作频繁及服务暂时异常。登录等需要根据错误代码执行跳转或租户选择的流程仍保留机器可读判断，但最终提示必须经过统一转换。

管理后台路由异常页只展示用户可理解的恢复建议和重试入口；原始异常仅用于开发日志，不在生产界面以代码块形式展示。

## 连续资源上传

资源列表页把上传组件作为“新增资源入口”，而不是“当前资源编辑器”。上传成功后不把返回资源绑定为组件的当前值，只提示成功并刷新资源列表，因此拖拽上传框会一直保留。

共享上传组件本身不改变现有单文件行为。主题 Logo、课程封面和课时资源仍可显示当前文件，并继续支持预览、替换和移除。

## 验证

- 为共享错误转换补充单元测试，覆盖中文透传、已知英文映射、401/403/404/409/413/429/5xx、网络失败、超时和未知错误兜底。
- 检查 Admin、PC、H5 的请求客户端及登录等直接捕获异常的页面均使用统一转换。
- 验证资源上传成功后上传框仍存在、列表刷新且成功提示只出现一次。
- 验证 Logo、课程封面和课时文件上传仍保留预览、替换及移除能力。
- 运行相关测试、类型检查和构建。

## 非目标

- 不修改服务端日志和开发调试信息的语言。
- 不将所有服务端内部错误改为中文，也不把内部错误细节暴露给用户。
- 不改变资源接口、存储方式或其他上传页面的交互。
