# 管理后台侧栏默认收起设计

## 目标

管理后台首次进入或刷新页面时，所有带子菜单的业务分组默认收起，避免资源管理、课程中心、学员管理、站点设置和安全审计同时展开造成侧栏过长。

## 交互行为

- 页面首次进入或刷新后，所有分组的展开键为空。
- 点击分组标题后正常展开或收起；同一次页面挂载期间保留用户当前操作结果。
- 页面内切换路由时，不自动展开当前页面所属分组，也不改变其他分组的手动展开状态。
- 刷新页面后重新恢复全部收起，不恢复上一次展开状态。
- 当前子菜单仍按路由保持选中态；分组收起时允许选中项暂时不可见，用户展开对应分组后即可看到。
- 首页概览、平台概览、教学工作台等无分组顶级菜单不受影响。
- 桌面侧栏整体折叠、平板紧凑模式和移动端抽屉继续沿用现有行为。

## 状态设计

`AdminLayout` 使用组件内 `openKeys` 状态管理分组展开，初始值固定为 `[]`。删除以下自动行为：

- 从 `sessionStorage` 恢复展开分组；
- 路由变化时合并 `requiredOpenGroups`；
- 展开变化后写入 `sessionStorage`；
- 强制保持当前路由所属分组展开。

`onOpenChange` 直接保存 Ant Design Menu 返回的展开键，因此仍允许用户同时手动展开多个分组；本次只改变默认与刷新行为，不改成手风琴单开模式。

## 测试策略

- 在导航配置中提供 `initialOpenGroups()`，由 `AdminLayout` 作为 `useState` 初始化器使用；单元测试验证它始终返回新的空数组。
- `onOpenChange` 直接使用 Ant Design Menu 返回的键，测试通过代码边界与构建验证不再合并路由分组。
- 删除只为自动展开服务的 `requiredOpenGroups` 及其旧测试，避免保留两套冲突规则。
- 运行管理端全部测试和生产构建。

## 验收标准

1. 登录后台或刷新任意后台页面后，所有业务分组均为收起状态。
2. 用户点击分组后可以正常展开多个分组，也可以逐个收起。
3. 页面内跳转不会自动展开当前分组，也不会重置用户刚刚手动展开的其他分组。
4. 刷新后不恢复历史展开状态。
5. 当前菜单选中态、权限过滤、整体侧栏折叠和移动端抽屉不受影响。

## 非目标

- 不改成一次只能展开一个分组的手风琴模式。
- 不删除菜单分组或调整菜单顺序。
- 不修改侧栏视觉样式、宽度、颜色或图标。
