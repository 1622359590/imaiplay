# 学员端自动展示已启用官方课程设计

## 背景与目标

学院管理员在课程管理中启用已发布的官方课程后，界面承诺学院学员可以立即开始学习。当前实现只写入 `tenant_official_courses`，而学员首页、课程列表、详情与资源授权都要求存在 `course_enrollments`，导致课程显示为“已添加”但学员端不可见。

本次修复让当前学院启用且平台已发布的官方课程自动对该学院所有有效学员可见，同时不为每个学员批量创建选课记录。现有租户课程和显式课程分配行为保持不变。

## 方案选择

采用动态合并方案：学员查询课程时，把有效选课课程与当前租户已启用的官方课程合并并按课程 ID 去重。

- 已启用但没有显式选课记录的官方课程按 `optional`（选修课）呈现。
- 官方课程已有有效选课记录时，保留记录中的 `required` 或 `optional` 类型，不重复展示。
- 停用、未发布或已删除的官方课程不展示，也不可访问课程详情、课时、附件或资源。
- 新加入学院的学员无需额外同步，登录后即可看到已启用官方课程。

未采用启用时批量创建选课记录，因为它需要处理大批量写入、启用失败回滚和未来新增学员同步。未采用逐人分配，因为它与“启用后学院学员即可学习”的产品语义不一致。

## 后端数据流

### 首页概览

`GET /api/v1/learner/overview` 先加载当前学员有效选课，再加载当前租户已启用且已发布的官方课程。显式选课课程优先，剩余官方课程以选修课加入概览；课程进度继续按当前学员的课时进度实时聚合。

### 课程列表与访问授权

`GET /api/v1/courses` 使用与首页相同的可见课程集合，保证列表口径一致。课程详情、课时内容、进度上报、附件下载和资源播放授权接受以下任一条件：

1. 当前学员具有有效选课记录，且课程对当前租户可见；
2. 课程是平台已发布的官方课程，且当前租户已启用。

跨租户、未启用或未发布课程继续统一拒绝访问。

### 停用行为

停用官方课程后不删除任何历史课时进度。课程立即从学员端消失并失去访问权限；重新启用后原有进度恢复展示。

## 前端行为

不修改学员端页面结构和课程卡样式。自动加入的官方课程使用现有“选修课”标签，参与“全部、选修课、已学完、未学完、分类”筛选；不计入必修课程完成数。

管理端弹窗文案保持不变，因为修复后“启用后学院学员即可开始学习”与实际行为一致。

## 测试策略

- 学员无选课记录时，已启用且已发布的官方课程出现在首页与课程列表，并标记为选修。
- 官方课程存在显式必修分配时只显示一次，并保留必修属性。
- 未启用、已停用、未发布的官方课程不展示且不可访问。
- 停用后访问课程详情、课时、附件和资源被拒绝。
- 不同租户的启用关系互不影响。
- 原有租户课程、课程进度、最近学习和必修统计测试继续通过。

## 验收标准

1. 学院管理员启用已发布官方课程后，本学院学员刷新首页即可看到课程。
2. 自动展示的官方课程默认为选修课，不计入必修总数。
3. 已显式分配的官方课程不重复，并保留其分配类型。
4. 停用后课程立即从学员端消失且无法继续访问，重新启用后历史进度仍在。
5. 不批量新增或删除 `course_enrollments` 数据。
6. 后端回归测试与受影响前端测试、构建通过。

## 非目标

- 不新增官方课程逐人分配界面。
- 不改变租户自建课程必须由管理员分配的规则。
- 不增加新的数据库表或迁移。
- 不修改课程卡视觉设计。
