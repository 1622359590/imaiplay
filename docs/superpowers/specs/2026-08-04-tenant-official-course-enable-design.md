# 学院启用官方课程设计

## 目标

让学院管理员在“课程管理”页面直接发现并启用平台已发布的官方课程，无需手动输入隐藏地址；启用后的课程立即可供该学院学员学习。

## 交互设计

- 在“课程管理”页右上角保留“新建课程”，并新增次要按钮“添加官方课程”。
- 点击“添加官方课程”后打开弹窗，列出平台官方课程。
- 每门课程展示名称、简介、发布状态和“已启用/未启用”开关。
- 切换开关后立即保存；成功时更新当前行并提示，失败时恢复原状态并展示错误。
- 只允许启用已发布课程；草稿课程仅供超级管理员维护，不出现在学院可选列表中。
- 左侧菜单同时增加“官方课程”入口，作为集中管理入口；课程管理弹窗是更快捷的主入口。

## 数据与权限

- 超级管理员继续负责创建、编辑、发布官方课程。
- 学院管理员只能查看平台官方课程及修改本学院的启用状态，不能编辑官方课程内容。
- `GET /backend/v1/official-courses` 对学院管理员返回每门课程在当前学院的 `enabled` 状态。
- `PUT /backend/v1/official-courses/:id/enabled` 继续负责启用和停用。
- 学院启用后不复制课程数据，仍引用平台统一维护的课程；平台更新内容后学院自动获得最新版本。

## 页面范围

- 修改学院后台侧边栏。
- 修改“课程管理”页快捷入口和官方课程选择弹窗。
- 修正“官方课程”页开关刷新后状态丢失的问题。
- 不改变学员端课程卡片样式，不增加课程复制、二次编辑或版本分叉能力。

## 异常处理

- 加载失败时保持弹窗并显示错误提示。
- 启用/停用失败时恢复开关原值。
- 没有已发布官方课程时展示空状态，并提示由平台管理员先发布课程。

## 验收标准

1. 学院管理员在课程管理页可以看到“添加官方课程”。
2. 弹窗只展示已发布官方课程，并正确显示当前学院的启用状态。
3. 启用后刷新页面仍保持开启，学员端课程列表可以看到该课程。
4. 停用后刷新页面仍保持关闭，学员端不再展示该课程。
5. 超级管理员原有官方课程维护流程不受影响。
6. 后端权限测试、管理端组件测试、构建和视觉检查通过。
