# 课程类型配置设计

## 背景

当前学员端会展示“必修课 / 选修课”，但这个值来自学员与课程的分配关系。管理员创建课程时没有设置课程类型，学员自行开始课程时系统还会默认创建“必修课”分配，导致界面展示了一个用户并未明确配置的判断结果。

课程分类已经用于内容和业务场景分组，例如“新员工培训”“产品知识”“培训回放”。课程分类回答“这是什么内容”，课程类型回答“是否必须完成”，两者应当独立存在。

## 产品规则

### 课程类型

- 每门课程必须且只能选择一种课程类型：`必修课` 或 `选修课`。
- 课程类型是课程自身属性，对学习该课程的所有学员一致。
- 新建课程时课程类型为必填项，不提供预选值，管理员必须主动选择。
- 编辑课程时可以修改课程类型。
- 平台官方课程同样由平台管理员在新建或编辑课程时设置课程类型。
- 现有历史课程迁移为“必修课”，避免数据库出现未定义状态；管理员可在后台编辑修改。

### 学员分配

- 学员分配只决定某名学员是否可以学习课程。
- 分配学员时不再选择“必修 / 选修”。
- 学员自行开始允许访问的课程时，创建的学习关系继承课程类型，不再无条件写入“必修”。
- 现有学习关系中的 `assignment_type` 不再作为页面展示和统计依据；课程类型成为唯一数据源。

### 课程分类

- 课程分类继续由站长在“课程分类”中维护。
- 分类用于后台课程整理以及学员端“所有分类”筛选。
- 分类名称不参与必修课或选修课判断。

## 后台界面

### 租户课程

在“新建课程”和“编辑课程”表单中增加必填的“课程类型”字段，选项显示完整名称：

- 必修课
- 选修课

未选择时不能提交，并提示“请选择课程类型”。

课程详情页的“学员分配”表格删除“分配类型”列；分配弹窗删除“分配类型”字段。

### 官方课程

平台官方课程的新建和编辑表单使用相同的必填“课程类型”字段。学院启用官方课程时直接继承平台配置的课程类型，不允许学院另行覆盖。

## 学员端界面

PC 与 H5 保持一致：

- 课程卡片显示课程分类标签；未设置分类时不显示分类标签。
- 课程卡片同时显示课程类型标签“必修课”或“选修课”。
- 课程详情页显示相同的课程分类和课程类型。
- 首页保留“全部 / 必修课 / 选修课 / 已学完 / 未学完”筛选。
- 右侧课程分类筛选继续使用后台维护的分类列表。
- “课程进度”中的必修课程总数和完成数根据课程自身类型统计。

## 数据模型与接口

- 在 `courses` 表增加非空课程类型字段，允许值为 `required`、`optional`。
- 迁移时将现有课程写为 `required`。
- 课程创建、更新及官方课程接口接收并校验课程类型。
- 学员概览和课程详情接口从课程记录返回课程类型。
- 后端拒绝空值及约定值之外的课程类型。
- 保留学习关系旧字段以兼容已有数据和渐进迁移，但不再作为产品判断的权威来源。

## 错误处理

- 后台表单在客户端阻止未选择课程类型的提交。
- 后端独立校验课程类型，非法值返回明确的参数错误。
- 历史数据迁移使用“必修课”兜底，确保部署后页面和统计立即可用。

## 验证范围

- 数据库迁移：历史课程默认成为必修课。
- 后端服务：创建和编辑必须提供合法课程类型。
- 学员概览：筛选、卡片、必修进度统计均读取课程类型。
- 自动开始课程：不再通过学习关系强制判定为必修。
- 后台：租户课程和官方课程表单必须主动选择类型。
- PC/H5：卡片和详情同时展示课程分类与课程类型。
- 回归：课程分类筛选、课程分配、学习进度和官方课程启用流程保持可用。
