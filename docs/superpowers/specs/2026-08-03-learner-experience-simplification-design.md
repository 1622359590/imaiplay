# 学员端极简化设计

## 目标

将 PC 与 H5 学员端统一简化为一条清晰的学习路径：

> 我的课程 → 课程详情与课时目录 → 课时学习

页面只展示真实课程数据和完成学习所需的操作。移除统计看板、学习计划、通知、证书、个人服务、英文装饰标题及其他没有真实数据支撑的内容。

## 范围

本次覆盖：

- PC 学员端 `web/pc`
- H5 学员端 `web/h5`
- 登录后的全局导航
- 我的课程页
- 课程详情页
- 课时学习页
- 空状态、加载状态与错误状态

本次不改动：

- 后端 API 和数据库结构
- 管理后台
- 登录认证流程
- 课程、章节、课时及学习进度的业务规则
- 租户 Logo、品牌色与欢迎语的配置能力

## 信息架构

### 路由

- `/`：我的课程，也是登录后的唯一首页。
- `/courses`：兼容旧入口，重定向到 `/`。
- `/recent`：PC 兼容旧入口，重定向到 `/`。
- `/profile`：H5 兼容旧入口，重定向到 `/`。
- `/courses/:id`：课程详情与章节目录。
- `/courses/:courseId/lessons/:lessonId`：课时学习。

旧入口采用重定向而非立即失效，避免已有书签或页面链接出现 404。

### 全局导航

PC 顶栏只保留租户品牌和退出操作，不再显示首页、全部课程、最近学习或学员身份占位。

H5 顶部只保留租户品牌和退出操作，移除通知入口及底部“首页 / 课程 / 我的”导航。详情和学习页仅显示返回操作与当前页面标题。

## 页面设计

### 我的课程

这是登录后的默认页，也是课程浏览的唯一入口。

页面内容按以下顺序展示：

1. 标题“我的课程”。
2. 简短说明“选择课程开始学习”。
3. 当前可学课程数量。
4. 课程列表。

每张课程卡只展示：

- 课程封面；无封面时使用简洁的品牌色占位。
- 课程名称。
- 真实课时数量。

不展示课程简介、讲师、预计时长、学员人数、类别标签、课程整体进度或独立按钮。现有课程列表接口不返回课程整体进度，前端不能使用默认值伪造进度。整张卡片可点击，减少重复操作。

PC 使用两列或三列自适应布局；H5 使用单列紧凑列表。两端的信息顺序保持一致。

### 课程详情

课程详情只承担两项职责：说明课程内容，以及让学员选择或继续课时。

顶部展示课程封面、课程名称、简介和课时数，不展示课程整体进度。

章节目录按课程既有顺序展示。每个课时只显示序号、名称和可选的真实时长，点击即可进入学习页。

现有课程详情接口不返回各课时的用户进度，因此目录不伪造“已完成”状态，也不提供无法可靠定位目标课时的“继续学习”按钮。学员直接从目录选择课时。若课程没有课时，显示“暂无可学习课时”。

### 课时学习

学习页只保留：

- 返回课程目录。
- 当前课时名称。
- 当前课时可访问的学习内容。
- 当前课时的真实学习进度。

视频进度继续沿用现有上报逻辑。文档课时保持现有的资源打开方式；文本课时不在本次界面简化中新增播放器能力。不新增虚构的学习时长或完成数据。

## 组件与复用

PC 与 H5 保持各自技术栈和组件目录，不进行跨项目组件共享，但使用相同的信息模型和状态文案。

重点组件边界：

- 页面壳：品牌、退出、内容容器。
- 课程卡：课程核心信息和点击导航。
- 课程列表：加载、空状态和自适应排列。
- 章节目录：章节与课时状态。
- 课时学习进度：统一限制在 0–100，并输出一致文案。

删除只服务于旧首页统计、通知、底部导航和个人中心的组件及样式。保留仍被登录页或管理品牌能力使用的通用样式。

## 数据流

1. 页面继续调用现有课程列表 API 获取课程基础信息。
2. 我的课程页直接将 API 返回结果渲染为课程列表，不生成本地统计、进度或演示数据。
3. 课程详情继续调用现有课程详情 API 获取章节和课时。
4. 学员从章节目录选择课时，不计算课程整体进度或自动选择“继续学习”课时。
5. 学习页继续调用现有单课时进度读取和上报 API。

不为界面展示补造学习时长、证书数量、完成课时数或周计划数据。

## 状态与错误处理

- 加载中：使用简洁骨架屏或加载提示，避免整页跳动。
- 无课程：显示“暂无可学习课程”，不显示统计卡或推荐占位。
- 课程不可访问：显示明确错误，并提供返回我的课程入口。
- 无课时：详情页保留课程信息，并显示“暂无可学习课时”。
- 学习资源缺失：显示“该课时尚未配置学习资源”，保留返回目录入口。
- 课时进度读取失败：课程内容仍可学习，课时进度显示为未开始；上报失败沿用现有非阻塞行为，不中断播放。
- 退出：清除认证信息并返回登录页。

## 视觉原则

- 使用白底、浅灰分隔和租户品牌色作为唯一强调色。
- 减少阴影、渐变、大面积欢迎区和装饰图形。
- 标题表达页面用途，不使用无业务含义的英文眉题。
- 一个页面最多一个高强调主操作。
- PC 与 H5 使用一致文案、状态和内容顺序。
- 保持键盘焦点、可点击区域、颜色对比度及移动端安全区支持。

## 验收标准

- 登录 PC 或 H5 后直接看到我的课程列表。
- PC 不再显示首页、全部课程、最近学习导航和页脚宣传语。
- H5 不再显示通知、学习计划、统计卡、底部导航和个人中心。
- 页面不显示任何硬编码的学习时长、证书数或统计数字。
- 课程列表只显示课程名称和真实课时数，不显示课程整体进度或状态。
- 课程详情不显示课程整体进度，学员可从章节目录进入任意课时。
- 视频和文档课时仍能按现有方式访问，视频进度仍能读取和上报。
- 旧的 `/courses`、`/recent` 和 `/profile` 路径可安全回到我的课程。
- PC 和 H5 前端构建通过。

## 测试策略

- 验证课程列表的加载、空列表和 API 失败状态。
- 验证课程卡只使用 API 返回的课程名称、封面和课时数，不生成进度或统计数据。
- 验证无章节、无课时、文本课时和资源缺失场景，确保文本课时维持现有行为。
- 验证课时进度读取、0–100 边界和进度上报行为。
- 验证旧路由重定向、退出登录和受保护路由。
- 分别运行 PC 与 H5 的 TypeScript 检查和生产构建。
- 对 PC 桌面宽度、窄屏以及常见 H5 宽度进行人工视觉检查。

## 实施边界

该设计只做学员端体验减法。课程整体进度和自动定位“继续学习”课时都依赖现有 API 未提供的数据，因此明确不在本次界面中展示或推断，也不为此修改后端。
