# 学员批量导入设计

## 目标

站长可在“学员与成员”页面通过 `.xlsx` 或 `.csv` 文件批量创建学员和讲师。导入允许部分成功：合法行立即创建，失败行返回明确原因，并可下载不含初始密码的错误明细。

## 范围

本次包含：

- 在“新增用户”旁增加“批量导入”入口。
- 提供标准导入模板下载。
- 支持 `.xlsx` 和 UTF-8 `.csv` 文件上传。
- 后端完成文件解析、逐行校验、租户内查重和用户创建。
- 展示成功/失败汇总，并提供失败明细 CSV 下载。
- 为后端导入流程和前端纯逻辑补充自动化测试。

本次不包含：

- 批量更新、删除或停用已有用户。
- 通过导入创建站长或总管理员。
- 自动生成密码、发送密码邮件或短信。
- 导入前的可编辑数据预览。

## 用户体验

“学员与成员”页头保留主按钮“新增用户”，并在其左侧增加次按钮“批量导入”。总管理员查看“全平台账号”时不显示这两个写入入口。

点击“批量导入”后打开弹窗，内容包括：

1. 模板下载按钮。
2. 字段及规则说明。
3. 支持拖拽或选择 `.xlsx`、`.csv` 文件的上传区域。
4. 单次最多 1000 条有效数据的提示。

上传期间禁止重复提交。导入完成后，弹窗展示导入总数、成功数和失败数。存在失败记录时显示“下载错误明细”按钮；用户可关闭弹窗，用户列表自动刷新以展示已成功创建的成员。

## 模板与数据规则

模板使用以下中文表头，顺序固定：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 姓名 | 是 | 去除首尾空格后不可为空 |
| 邮箱 | 是 | 去除首尾空格、转为小写，并满足邮箱格式 |
| 手机号 | 否 | 作为文本读取，去除现有规则允许的分隔字符后必须满足手机号规则 |
| 角色 | 否 | 留空默认为学员；接受“学员”、`learner`、“讲师”、`instructor` |
| 初始密码 | 是 | 至少 8 个字符 |

空白行忽略。角色为站长、总管理员或未知值时，该行失败。

导入过程中沿用现有用户服务的租户隔离、邮箱唯一性、手机号唯一性和密码哈希逻辑。同一文件内发生重复时，第一条能够成功创建的记录保留，后续重复行失败。数据库中已有相同邮箱或手机号时，该行失败。

文件必须是 `.xlsx` 或 `.csv`，表头必须完全匹配标准模板。解析后的非空数据超过 1000 行时整份文件拒绝，避免长请求和资源滥用。CSV 使用 UTF-8 编码；下载文件带 UTF-8 BOM，保证中文在常见表格软件中正常显示。

## 后端设计

新增仅限站长访问的接口：

```text
POST /backend/v1/users/import
Content-Type: multipart/form-data
file: <xlsx-or-csv>
```

响应数据结构：

```json
{
  "total": 4,
  "succeeded": 3,
  "failed": 1,
  "errors": [
    {
      "row": 5,
      "name": "示例学员",
      "email": "duplicate@example.com",
      "phone": "",
      "role": "learner",
      "reason": "邮箱已存在"
    }
  ]
}
```

响应和错误日志均不得包含初始密码。文件级错误（类型错误、表头错误、无法解析、超过 1000 行）使用现有错误响应格式并拒绝整份文件。行级错误进入 `errors`，不会阻止其他合法行创建。

实现分为三个边界清晰的单元：

- 文件解析器：把 CSV/XLSX 转为带原始行号的导入行，不访问数据库。
- 导入服务：规范化字段、映射角色、调用现有单用户创建逻辑并收集逐行结果。
- HTTP 处理器：验证权限与上传文件，选择解析器并返回汇总。

XLSX 解析使用 Go 侧维护良好的工作簿库；CSV 使用标准库 `encoding/csv`。接口继续使用请求上下文中的租户信息，客户端不能指定 `tenant_id`。

## 前端设计

新增批量导入弹窗组件和用户 API 方法。上传使用 `multipart/form-data`。模板可由前端以静态 CSV 内容生成下载，表头与后端常量保持相同，并包含一行示例数据；用户也可在 Excel 中打开 CSV 模板后另存为 `.xlsx`。

错误明细由前端根据服务端返回结果生成 CSV，列为：

```text
行号,姓名,邮箱,手机号,角色,失败原因
```

错误文件不包含“初始密码”列。CSV 单元格按标准规则转义，下载内容带 UTF-8 BOM。

## 错误处理与一致性

导入采用逐行独立创建，不开启覆盖整批的数据库事务，以符合“部分成功”的产品约定。每行都复用现有创建服务，因此与单条新增保持相同的权限、规范化、唯一性和密码安全行为。

若某行因并发写入在最终创建时触发唯一索引冲突，则该行记录为重复错误，其他行继续处理。服务器异常只影响对应行；无法继续读取文件的解析错误属于文件级错误，整份拒绝。

## 测试策略

后端自动化测试覆盖：

- 仅站长可导入，总管理员和其他角色被拒绝。
- CSV 与 XLSX 的正确表头、空白行和原始行号。
- 中文/英文角色映射及角色留空默认学员。
- 姓名、邮箱、手机号、密码和角色校验。
- 数据库已有重复以及文件内重复。
- 多租户隔离：其他租户的相同邮箱不影响当前租户。
- 部分成功结果及响应中不存在密码。
- 文件类型、错误表头、解析失败和 1000 行上限。

前端自动化测试覆盖模板内容、错误明细 CSV 的转义与密码排除、API 请求形态，以及能独立测试的导入结果展示逻辑。最后运行 Go 全量测试、管理端测试与生产构建。

## 验收标准

- 站长可从“学员与成员”页面下载模板并上传 `.xlsx` 或 `.csv`。
- 合法行创建到当前租户，角色留空时创建为学员。
- 非法行不创建，且页面准确显示成功/失败数量。
- 失败明细可下载，包含行号和原因，不包含任何初始密码。
- 单条新增用户流程和总管理员只读列表不受影响。
