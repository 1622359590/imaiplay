# 强制 HTTPS 与学员端选中态同步设计

## 目标

完成自定义域名绑定时，确保用户通过 HTTP 访问会自动跳转到 HTTPS；同时让学员端课程筛选标签完整使用租户在主题设置中配置的选中背景色、文字色和图标色。

## 强制 HTTPS

### 调用顺序

域名绑定流程保持现有五个步骤，并在第 4 步内部按以下顺序执行：

1. 申请并部署 Let's Encrypt 证书。
2. 轮询确认宝塔站点的证书已经生效。
3. 调用宝塔网站管理接口 `POST /site`，参数为 `action=HttpToHttps` 与 `siteName=<自定义域名>`。
4. 仅在强制跳转成功后进入第 5 步，保存租户自定义域名并将绑定状态设为 `ready`。

这样不会提前开启 HTTPS 跳转，也不会在跳转尚未启用时向租户显示绑定成功。

### 组件边界

- `DomainPanel` 增加 `EnableHTTPSRedirect(domain string) error`，由域名绑定服务依赖抽象能力，不依赖宝塔请求细节。
- 宝塔客户端负责组装并签名 `HttpToHttps` 请求，沿用现有 API 错误解析。
- 域名绑定编排器在证书确认成功后调用该能力。

### 失败与回滚

强制 HTTPS 是绑定成功的必要条件。宝塔返回失败、请求超时或接口异常时：

- 当前绑定进入 `setup_failed`，提示“开启强制 HTTPS 失败，请稍后重试或联系平台管理员”。
- 沿用现有失败处理，删除本轮创建的宝塔站点并释放域名占用。
- 不写入租户的 `CustomDomain`，不记录成功审计事件。

不启用宝塔全局 HTTPS，也不直接手写 Nginx 301 规则，避免影响同机其他站点或与宝塔生成的 SSL 配置冲突。

## 学员端选中态同步

### 根因

学员端已经把租户的三个选中态颜色写入 CSS 变量：

- `--tenant-selected-background`
- `--tenant-selected-text`
- `--tenant-selected-icon`

课程筛选标签的背景色已经读取变量，但 Ant Design 对激活标签按钮的内置选择器优先级更高，覆盖了项目设置的文字色。因此背景色生效而“全部”文字不可见。底部选中指示条仍使用品牌主色，也没有反映独立的选中图标色。

### 修复方案

保留现有 Ant Design `Tabs` 和页面结构，只调整学员端样式边界：

- 激活标签容器背景使用 `--tenant-selected-background`。
- 激活标签按钮文字使用更明确的项目选择器，并以 `--tenant-selected-text` 覆盖组件库状态色。
- 激活标签底部指示条使用 `--tenant-selected-icon`，作为无图标标签的选中强调色。
- 普通标签、悬停状态、课程筛选逻辑和分类下拉框保持不变。

该修复只处理 PC 学员端截图中的课程筛选标签。H5 底部导航和后台侧栏已经消费相同的选中态变量，不重复改写。

## 测试标准

### 后端

- 宝塔客户端向 `/site` 发送 `action=HttpToHttps` 与正确 `siteName`。
- 证书生效后才调用强制 HTTPS。
- 强制 HTTPS 成功后才保存租户域名并进入 `ready`。
- 强制 HTTPS 失败时删除站点、释放占用，并且不保存租户域名。

### 前端

- PC 学员端激活筛选标签背景使用选中背景变量。
- 激活标签按钮文字使用选中文字变量，并能覆盖 Ant Design 内置颜色。
- 选中指示条使用选中图标变量。
- PC 单元测试和生产构建通过。

### 全量验证

- `go test ./... -count=1`
- `go vet ./...`
- 后台、PC 和受影响工作区的前端测试与生产构建通过。
- `git diff --check` 无格式问题。

## 发布顺序

实现与验证完成后，遵循 ImaiPlay 项目约定：先推送 Gitee `main`，再推送 GitHub `main` 触发部署流程，并确认 GitHub Actions 结果。

## 范围限制

本次不启用全局 HTTPS、不提供客户证书上传、不更换课程筛选组件，也不调整用户已经选择的主题色；若颜色对比度较低，继续由现有主题设置页提示用户。
