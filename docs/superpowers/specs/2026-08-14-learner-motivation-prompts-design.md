# 学员激励弹窗与昨日学习简报设计

## 目标

在 PC 与 H5 学员端加入服务端驱动的激励弹窗，让用户进入学习首页时获得与自身阶段相符的反馈：

- 新账号首次成功登录后看到一次欢迎引导，并能直接开始第一门推荐课程。
- 已有学习经历的用户每天首次进入时看到一次昨日学习简报。
- 昨日没有学习记录时不展示空报表或负面数字，改为轻量回归鼓励。
- PC、H5 和不同设备共享同一展示状态，不因清除浏览器缓存而重复弹出。
- 所有学习成果、比较数据和推荐课程来自真实后端数据，不在前端伪造。

本功能不增加积分、勋章、连续打卡、证书或运营配置后台。它只完成“看见成果—获得鼓励—明确下一步—继续学习”的最小闭环。

## 已确认的产品决策

- “新用户”定义为账号创建后的首次成功登录，而不是“还没有学习记录”或“第一次进入学习首页”。
- 新用户欢迎弹窗只出现一次。
- 老用户简报按上海时区自然日计算，每天首次进入学习首页时最多出现一次。
- 新用户主按钮直接进入第一门推荐课程。
- 老用户主按钮直接进入上次学习位置。
- PC 与 H5 使用同一数据和频率规则，仅调整视觉布局。
- 历史账号在功能上线时默认视为老用户，避免把已有学员误判成新用户。

## 方案选择

采用方案 A：服务端统一激励中心。

服务端负责用户阶段判断、昨日统计、同租户比较、推荐课程和展示状态；PC 与 H5 只负责渲染返回的弹窗模型并回传已展示确认。该方案能保证跨设备一致，也便于以后扩展更多真实激励规则。

未采用方案 B：只使用 `localStorage` 记录是否展示。该方案实现快，但换设备、无痕窗口或清除缓存后会重复弹窗，不能满足账号级频率要求。

未采用方案 C：把弹窗数据直接塞入登录响应。该方案会把每日简报和学习首页强耦合，刷新令牌、组织选择登录和已登录直达首页的行为也会产生分歧。

## 用户状态与优先级

服务端每次只返回一种状态，优先级固定如下：

1. `welcome`：新账号已完成首次成功登录，但欢迎弹窗尚未展示。
2. `daily_summary`：老用户昨日存在有效学习时长，且当日简报尚未展示。
3. `reengagement`：老用户昨日没有有效学习时长，且当日回归鼓励尚未展示。
4. `none`：今日已展示、用户无可访问课程或当前没有适合的激励内容。

首次登录当天优先展示 `welcome`，不叠加昨日简报。用户确认欢迎弹窗后，最早从下一自然日开始进入老用户简报流程。

## 新用户欢迎弹窗

### 内容

- 标题：“欢迎开启你的学习旅程”。
- 说明：“从第一门课程开始，把每一次学习积累成成长。”
- 展示推荐课程名称、必修/选修属性和课时数量。
- 主按钮：“开始第一门课程”。
- 次操作：“稍后再看”或关闭按钮。

### 推荐课程规则

按以下顺序选择第一个有课时且当前可访问的课程：

1. 用户被分配的未完成必修课。
2. 当前租户启用且可访问的未完成官方必修课。
3. 用户被分配的其他未完成课程。
4. 当前可访问的第一门课程。

同一优先级按分配时间或课程稳定排序选择，结果必须可重复。推荐课程有课时时，主按钮进入其第一个未完成课时；没有可访问课程时不显示无效主按钮，弹窗改为提示“当前暂无学习任务”，关闭后仍完成欢迎展示确认。

## 老用户昨日简报

### 昨日有学习

简报只展示真实可计算的结果：

- 昨日有效学习时长。
- 昨日学习过的去重课时数量。
- 昨日完成的课时数量。
- 昨日完成的课程数量。
- 与前一日学习时长的变化；前一日为零时不显示无意义的百分比增长。
- 当前必修课程完成数与总数。
- 推荐继续学习的课程、最近课时和当前课程进度。

鼓励话术由确定性规则生成，不调用生成式模型。例如：

- 完成课程时：“昨天完成了 1 门课程，做得很好。”
- 有学习但未完成课程时：“昨天投入了 28 分钟，学习节奏正在形成。”
- 比前一日增长时：“比前一天多学习 12 分钟，继续保持。”

### 同租户比较

只有同时满足以下条件才显示“超过 X% 的昨日活跃学员”：

- 当前用户昨日有效学习时长大于零。
- 当前租户昨日有效学习的学员不少于 10 人。
- 比较范围只包含同租户、状态正常且昨日有效学习时长大于零的学员。

百分位计算为“学习时长严格低于当前用户的人数 / 昨日活跃学员人数”，向下取整为整数。并列用户不互相超越，文案明确限定为“昨日活跃学员”，不能写成“超过全公司 X% 的学员”。样本不足时隐藏该指标，改用个人完成情况或与前一日的变化。

### 昨日无学习

不展示“昨日 0 分钟”、下降百分比或排名。弹窗改为：

- 标题：“欢迎回来，继续你的学习节奏”。
- 展示上次学习课程、最近课时和当前进度。
- 主按钮：“继续学习”，进入上次学习位置。
- 没有历史学习位置时，使用与新用户相同的推荐课程规则，但文案保持回归语气。
- 没有任何可访问课程时返回 `none`，不弹出没有行动价值的空弹窗。

## 展示频率与确认

### 服务端状态

新增账号级学员激励状态，至少包含：

- `user_id` 与 `tenant_id`。
- `first_login_at`：首次成功登录时间。
- `welcome_seen_at`：欢迎弹窗成功呈现时间。
- `last_daily_prompt_date`：最近一次成功呈现老用户弹窗的上海时区日期。

账号创建时建立状态记录。密码登录、短信登录和组织选择登录最终都通过同一个“完成租户登录”路径原子地写入 `first_login_at`，只有第一次成功写入。

迁移上线时，为所有已有学员建立已完成欢迎展示的状态；这些账号进入老用户流程。上线后新建账号才能进入精确的首次登录欢迎流程。

### 呈现确认

- 学员端先正常渲染学习首页，再异步请求激励模型。
- 弹窗实际挂载并可见后，客户端向服务端确认已呈现。
- `welcome` 确认后永久不再返回。
- `daily_summary` 或 `reengagement` 确认后，当天 PC、H5 和其他设备均不再返回。
- 用户点击主按钮时也必须补发确认，然后导航；确认失败不能阻止进入课程。
- 请求失败或确认失败不遮挡首页、不显示全页错误，也不影响学习 API。

## API 设计

### 获取激励模型

`GET /api/v1/learner/motivation`

响应为统一判别联合模型：

```json
{
  "kind": "welcome",
  "prompt_key": "opaque-current-user-key",
  "study_date": "2026-08-13",
  "title": "欢迎开启你的学习旅程",
  "message": "从第一门课程开始，把每一次学习积累成成长。",
  "metrics": null,
  "comparison": null,
  "course": {
    "id": "course-id",
    "title": "新员工入职培训",
    "assignment_type": "required",
    "progress_percent": 0,
    "lesson_id": "lesson-id",
    "lesson_title": "欢迎视频",
    "last_position_seconds": 0
  }
}
```

`kind=none` 时只返回类型，不返回无意义的空指标。`prompt_key` 是绑定当前用户和当前待展示状态的不透明短期标识，客户端不能提交任意用户 ID 或日期。

### 确认已呈现

`POST /api/v1/learner/motivation/ack`

```json
{
  "prompt_key": "opaque-current-user-key"
}
```

接口必须幂等。重复确认返回成功；过期、跨用户或跨租户标识返回明确的 400/403，且不能修改其他账号状态。

## 数据来源与统计口径

- 昨日和前一日学习时长来自 `learning_daily_stats`。
- 昨日学习课时来自 `learning_time_reports`，按上海时区对应的 UTC 时间区间过滤并按 `lesson_id` 去重。
- 昨日完成课时来自 `lesson_progress.completed_at`。
- 昨日完成课程由课程全部有效课时在昨日完成后推导，零课时课程不算完成。
- 必修完成数、推荐课程、最近课时和课程进度复用学员概览的可见性与完成规则，不能另建一套不一致算法。
- 学习时长继续只统计后端接受的有效心跳增量。
- 已删除、停用、未分配或当前不可访问的课程不能出现在弹窗中。

所有日期边界使用 `Asia/Shanghai`，不能以服务器本地时区或浏览器时区直接截断 UTC 日期。

## PC 与 H5 体验

### 共同视觉原则

- 延续已选择的极简学习首页：白色/浅色表面、细边界、极轻阴影和充分留白。
- 租户主色只用于标题重点、进度和主按钮。
- 所有颜色来自现有学员主题 CSS 变量和后台可配置主色派生变量，不写死颜色字面量。
- 不使用大面积渐变、厚重 3D 阴影、奖杯、烟花、积分或游戏化装饰。
- 弹窗出现使用轻微淡入与 4–8px 位移；开启 `prefers-reduced-motion` 时取消位移动画。

### PC

- 使用居中、宽度约 520–620px 的轻量对话框。
- 昨日简报最多一行 3–4 个紧凑指标，不嵌套统计卡。
- 主按钮与关闭操作清晰分级，背景遮罩不过暗。

### H5

- 使用底部半屏卡片，不把 PC 对话框按比例缩小。
- 指标改为两列或纵向信息行，主按钮固定在卡片内容底部但不遮挡正文。
- 适配安全区和软键盘，不允许内容被底部导航覆盖。

### 可访问性

- 对话框具备标题关联、焦点锁定、初始焦点、Escape/返回键关闭和关闭后的焦点恢复。
- 图标只作辅助，关键结果必须有文字。
- 排名、增减和完成状态不能只依赖颜色。
- 主按钮、关闭按钮和 H5 触摸目标满足现有组件最小尺寸要求。

## 前端组件边界

共享层提供：

- 激励 API 类型和严格的响应归一化。
- 时长、变化量和激励话术的纯函数。
- 推荐目标路由所需的通用字段，不直接依赖 React Router。

PC 与 H5 分别提供：

- `LearnerMotivationPrompt` 容器，负责请求、展示确认和导航。
- `WelcomePrompt`、`DailySummaryPrompt`、`ReengagementPrompt` 三种展示模板。
- 平台自己的 Modal/Popup 外壳和响应式样式。

首页只负责在概览稳定后挂载容器，不承担统计规则或跨设备状态判断。

## 错误处理

- 激励接口失败：静默跳过，首页保持可用，可记录开发日志但不弹错误通知。
- 返回课程已失效：隐藏主按钮或返回 `none`，不能导航到不可访问页面。
- 展示确认失败：当前弹窗仍可关闭或进入课程，后续访问允许再次尝试确认。
- 昨日统计部分缺失：只展示可信指标，不用零值补齐未知数据。
- 排名样本不足：完全隐藏排名模块，不显示占位符。
- 多设备并发：确认接口幂等，以服务端最终状态为准。

## 测试与验收

### 后端

- 三种登录方式都只写入一次 `first_login_at`。
- 历史账号迁移后不会被识别为新用户。
- 欢迎弹窗确认后永久不再返回。
- 老用户简报按上海时区跨日，并且每天最多成功呈现一次。
- 昨日有学习、昨日无学习、无课程、课程失效均返回正确类型。
- 时长、课时去重、完成数、前日变化和租户隔离正确。
- 活跃人数小于 10 时不返回百分位；达到阈值时并列和百分位计算正确。
- 确认接口覆盖幂等、过期标识、跨用户和跨租户攻击。

### 共享与前端

- API 响应归一化拒绝非法类型、负时长、越界百分比和缺少导航目标的数据。
- PC 与 H5 都覆盖欢迎、昨日简报、回归鼓励和 `none`。
- 弹窗在首页主体加载后出现，失败时不阻塞课程展示。
- 主按钮先尝试确认再导航，确认失败仍能导航。
- 同一天服务端返回 `none` 时不会再次展示。
- 焦点、键盘关闭、返回键、H5 安全区和减少动画均有契约或行为测试。
- 主题测试确认新增样式只使用学员 CSS 变量，后台修改主色后弹窗同步变化。

### 发布门禁

- `go test ./...`
- Shared、PC 与 H5 完整测试。
- PC 与 H5 生产构建。
- 现有三端 bundle budget 门禁。
- `git diff --check`。

## 范围外

- 管理后台自定义激励文案或开关。
- 积分、徽章、连续学习天数、证书与排行榜页面。
- 跨租户比较或公开其他学员姓名。
- 推送通知、短信或邮件学习提醒。
- 周报、月报和历史趋势图。
- 使用生成式 AI 动态生成文案。
